## Description
A new endpoint is needed to support Users wanting to create an archive of their archive so to speak.  
This may be for data redundancy or sharing it to another peer. Currently planning to support archival of specific snapshots  
and the entire web archive as a whole.


## Specs
(Taken from the glorious ../../API.org file)
** POST =/snapshots/archive
    Creates a Zip archive of the entire web archive. Or potentially specific snapshots
*** Request
    Content-Type: application/json
    #+begin_src json-ts
      {
          // (string optional) What we want to be in our archive. Present in case archival wants to be extended to specific snapshots
          // default: "ALL"
          // NOTE "ALL" refers to the entire web archive collection, including the db file!
          "archive": "ALL"
      }
    #+end_src
*** Success Response
    Code: 200 \\
    Content-Type: application/zip \\
    Content-Disposition: attatchment; filename="archive_<archive>.zip"

    The response body contains the zip archive as binary data that gets streamed to the reciever.

*** Error Responses
      400 and 500 error responses as defined in the general API.org file
    - Code: 404 \\
      Content-Type: application/json

      Indicates that the provided "archive" payload item is not "ALL" or refers to a non-existent snapshot.
