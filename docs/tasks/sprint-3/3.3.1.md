# Add Endpoint to Enable Batch Deletion
    
## Description
A new endpoint is needed in order to support batch deletion. This is to make the goal of allowing Users to organize / clean up their archives more
efficient on the backend.  

## Specs
- 'POST /snapshots/delete' with '{"ids": ["snapshot-1", "snapshot-2", ...]}' returns HTTP 202. Any requests made without such body are a 400. If an
error occurs while processing, we return a 500
- A non 202 result should guarantee that no actual data got modified
- The snapshot ids provided should be handled permissively. We don't freak if one (or all) snapshot ids don't exist. Or if a file doesn't get deleted
for one of the snapshots. This is because generally, if the files 'fail' to get deleted, it is because they have already been deleted or were moved.
            
## Requirements 
- Avoid re-using existing delete endpoint to delete a singular snapshot
- Non 202 responses should only occur before accessing the database or in the middle of it. Never after commiting transaction.
        
## Acceptance Criteria
- We are able to use the new endpoint to fully delete multiple snapshots at once
- Responsd with 202 if database files are deleted, even if we couldn't find the files on disk to delete
- If we would respond with 400 or 500, no data stored will be mutated.
