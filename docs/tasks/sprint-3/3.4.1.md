# Save complete embedded videos after partial responses

## Description

When a browser requests an embedded MP4 or WebM in byte ranges, the scraper can save one partial response as the entire video. This task fixes Issue #29 for direct video URLs whose servers also allow a full download.

## Specs

- `PageScraper.archive_page` continues to save directly embedded MP4 and WebM resources returned as complete responses.
- For a partial HTTP 206 video response, the scraper attempts one bounded full download per video URL during a snapshot, with no Range header. If successful, it stores the complete file and records the full response in the archive database.
- If a full download is unavailable, the page can still be saved. The scraper logs that the video could not be saved completely and leaves no incomplete video file or successful file record for that resource.

## Requirements

- Handle direct MP4 and WebM resources in the existing Playwright scraper.
- Bound the retry by elapsed time and downloaded bytes. Preserve existing behavior for other resource types.
- Segment assembly, streaming playlists, and frontend playback changes are outside this task.

## Acceptance criteria

1. An embedded video returned in full is saved byte-for-byte without a recovery request.
2. If the browser first receives only one range and the same URL supports a full download, the archive contains one complete video byte-for-byte, with a successful full-response status and no partial Content-Range metadata.
3. If the URL never returns a complete video, the snapshot remains available and a warning is logged. No truncated video is written or registered in the archive.
