# Connect the desktop UI to real offline archives

## Description

This task carries over from Sprint 2. It connects the unified desktop UI to the archive backend so a user can save a webpage, find its snapshot, and open the locally stored page or its source.

## Specs

- The desktop **Save a page** action submits the URL to the local backend through `WebberAPI.create_snapshot` and refreshes the archive list after a successful save.
- The archive search queries the backend and matches URL fragments as case-insensitive literal text.
- Opening a snapshot loads its stored HTML and assets in **Page** view. **Raw HTML** shows the stored source for the same snapshot.
- The normal desktop launch uses the real backend. Sample archives are available through the explicit demo mode.

## Requirements

- Use the team's shared API for frontend archive requests.
- Keep the Qt event loop responsive during capture and allow searches to read committed snapshots while a capture is writing.
- A backend restart must retain saved snapshots and files.

## Acceptance criteria

1. A user can save a real webpage from the desktop and open its snapshot from the archive list. With the source server stopped, **Page** displays the saved text, style, and image, and **Raw HTML** displays the stored source. The same snapshot and source can be reopened after restarting the backend.
2. Searching with a case-insensitive URL fragment finds the saved snapshot. Characters such as `.` and `[` are treated literally.
3. While a capture holds an uncommitted write, searches return existing snapshots. The new snapshot appears after the write commits.
