* Common Object Types
** =timespec=
   Represents a point in time or a span of time. When representing a point in
   time, *always UTC (e.g. GMT timezone)*. See =timespec(3type)= for rationale.
   #+begin_src json-ts
     {
         // (integer) second part
         "sec": 10,
         // (integer) nanosecond part (in range [0,999'999'999])
         "nsec": 10
     }
   #+end_src

* Common Error Responses
  Note that all API routes described below have the following additional error
  responses.
  - Code: 500 (Internal Server Error) \\
    Content-Type: application/json

    Sent when something unexpected happened that prevented the operation from
    being completed (network error, DNS resolution error, file permission error,
    file quota reached, read only FS, etc.).

    #+begin_src json-ts
      {
          // (string) Message as to why the request failed
          "message": "..."
      }
    #+end_src
  - Code: 400 (Bad Request) \\
    Content-Type: application/json

    Sent when one of the request parameters is of the wrong type or malformed
    (e.g. bad URL or request type).

    #+begin_src json-ts
      {
          // (string) Message as to why the request failed
          "message": "..."
      }
    #+end_src

* Routes
** POST =/snapshots/create=
   Create a snapshot of a webpage. Note that this should succeed even if the
   page returned an error code (e.g. 404) because that is still the real content
   of the page.
*** Request
    Content-Type: application/json
    #+begin_src json-ts
      {
          // (string) URL to archive (fully qualified)
          "url": "https://www.example.com/path/to/file?param1=val&param2=val",
          // (object) Some extra options
          // TODO To start, the UI can probably just have a basic list form
          // for testing, but in the future we might want a cleaner UI for
          // common headers like basic auth or cookies.
          "request_options": {
              // (string) HTTP request method (e.g. get, post, etc.)
              "method": "GET",
              // (object of arrays) HTTP request headers
              "headers": {
                  // NOTE because headers can be repeated, these must be arrays
                  "Authorization": ["Basic ..."], // example, for basic auth
                  "Set-Cookie": ["...", "..."]
              }
          }
          // Example of something that might be added in a future sprint
          // TODO (object) Crawing options
          // "crawl": {
          //     // (boolean) do crawing
          //     "enable": true,
          //     // NOTE that one of the following (`depth` or `limit_hosts`) is
          //     // required.
          //     // (integer, optional) maximum depth
          //     // default: infinity
          //     "depth": 3,
          //     // (array of strings, optional) hosts to scan (supports globs)
          //     // default: ["*"]
          //     "limit_hosts": ["www.example.com", "example.com", "*.abc.com"]
          // }
      }
    #+end_src
*** Success Response
    Code: 201 (Created) \\
    Content-Type: application/json
    #+begin_src json-ts
      {
          // (string) *unique* ID representing this snapshot, format is an
          // implementation detail, but it should be not require encoding to
          // convert to a URL
          "id": "..."
      }
    #+end_src
*** Error Responses
    Only the global error responses defined above apply.

** GET =/files/{FILE_ID}=
   Get information about the file =FILE_ID=.
*** Request
    Get requests have empty bodies.
*** Success Response
    Code: 200 (OK) \\
    Content-Type: application/json
    #+begin_src json-ts
      // This example is for the file:
      // https://www.example.com:443/path/to/file?param1=val&param2=val
      {
          // (string) echo back FILE_ID
          "id": "...",
          // (string) snapshot to which this file belongs
          "snapshot": "...",
          // (string) pretty URL to request this file (note the SNAPSHOT_ID
          // needs to be replaced by the ID). The port, protocol, and host are
          // all one path component. The path follows as usual. The parameters
          // are the actual request parameters (not double encoded).
          "url": "/data/SNAPSHOT_ID/https://www.example.com/path/to/file?param1=val&param2=val",
          // (string) protocol used to request the file
          "protocol": "https",
          // (integer) port used to request the file
          "port": 443,
          // (string) (remote) host of the file
          "host": "www.example.com",
          // (string) relative path to file on (remote) host
          "path": "path/to/file",
          // (object) information about the request
          "request": {
              // (timespec) time the file request was made
              "sent_time": { ... },
              // (string) HTTP request method (e.g. get, post, etc.)
              "method": "GET",
              // (object of arrays) HTTP request headers
              "headers": {
                  // NOTE because headers can be repeated, these must be arrays
                  "Authorization": ["Basic ..."], // example, for basic auth
                  "Set-Cookie": ["...", "..."]
              },
              // (object of arrays) request parameters (the ones in the URL)
              "parameters": {
                  // NOTE because parameters can be repeated, these must be
                  // arrays
                  "param1": ["val"],
                  "param2": ["val"]
              }
          },
          // (object) information about the response
          "response": {
              // (timespec) time the response was received
              "received_time": { ... },
              // (integer) code the server responded with when serving this file
              "code": 200,
              // (object of arrays) response headers
              "headers": {
                  // NOTE because headers can be repeated, these must be arrays
                  "Content-Type": ["text/html"],
                  "X-Coolness-Level": ["10000"]
              }
          }
      }
    #+end_src
*** Error Responses
    - Code: 404 \\
      Content-Type: application/json

      Indicates that the passed =FILE_ID= refers to a non-existent file.

** GET =/files/{FILE_ID}/data=
   Return contents of file FILE_ID (lookup files by ID). Note that there is no
   way to distinguish a failure in the archive server and a failure during the
   original request in this case. That is, this route directly returns the
   response originally received by the server, error status and all.
*** Request
    Get requests have empty bodies.
*** Success Response
    Code: (depends on original response)
    Content-Type: (depends on original file)
    The response body is the content of the file, as the system originally
    returned it.
*** Error Response
    Note that these error responses are mostly meaningless for the reasons
    stated above.
    - Code: 404 \\
      Content-Type: application/json

      Indicates that the passed =FILE_ID= refers to a non-existent file.

      #+begin_src json-ts
        {}
      #+end_src

** (VARIES) =/data/{SNAPSHOT_ID}/{PATH ...}=
   Query files by original URL. The PATH is the URL (including the port, domain
   name, etc.) of the original file to query. The SNAPSHOT_ID is the snapshot to
   query this path from. The PATH is in this form:
     /data/SNAPSHOT_ID/{HOST}/{COMPONENTS...}?{PARAMS...}
   The HOST field contains the protocol, port, and hostname. All of these are
   combined (e.g. https://www.example.com:443, then URL encoded). The COMPONENTS
   are the file path components. The PARAMS are the actual parameters of the
   original request (that is, the parameters to this request are the same as
   those to the original request.

   Note that the same error response ambiguity mentioned above applies here too.
*** Request
    Probably empty (we probably don't need this right now)
*** Success Response
    Code: (depends on original response)
    Content-Type: (depends on original file)
    The response body is the content of the file, as the system originally
    returned it.
*** Error Response
    Note that these error responses are mostly meaningless for the reasons
    stated above.
    - Code: 404 \\
      Content-Type: application/json

      Indicates that the passed =FILE_ID= refers to a non-existent file.

** QUERY =/search/snapshots=
   Make a general query for a list of snapshots.
*** Request
    Content-Type: application/json
    #+begin_src json-ts
      {
          // (timespec, optional) don't return snapshots created before this
          // default: -infinity seconds UTC
          "start_time": { ... },
          // (timespec, optional) don't return snapshots created after this
          // default: +infinity seconds UTC
          "end_time": { ... },
          // (string, optional) regexp to match against original snapshot URL
          // default: any URL
          "url": "^https?//:abc*.(?:com|org)/(?:.+/)(?:.*[^/])?$"
      }
    #+end_src
*** Success Response
    Code: 200 (OK) \\
    Content-Type: application/json
    #+begin_src json-ts
      // (array of strings) list of snapshot IDs that matched the above search
      [
          "...",
          "...",
      ]
    #+end_src
*** Error Response
    Only the global error responses defined above apply.

** QUERY =/statistics=
*** Types
**** =interval=
     Represents an interval of time. If =start= > =end=, the server should
     return a 400 status code.

     When matched against a snapshot, this is the snapshots =start_time= field.

     #+begin_src json-ts
       {
           // Note that start is inclusive, but end is exclusive. That is, the
           // interval is [start, end).

           // (timespec or null) start time of the interval
           // a value of `null` means -infinity
           "start": {...},
           // (timespec or null) end time of the interval
           // a value of `null` means infinity
           "end": {...}
       }
     #+end_src
**** =statistics=
     Represents statistics over an interval.
     #+begin_src json-ts
       {
           // (interval) interval over which these statistics were taken
           "interval": {...},
           // (integer) number of snapshots started during this interval
           "snapshots": 0,
           // (integer) number of files belonging to snapshots during this
           // interval
           "files": 0,
           // (integer) sum of logical file sizes (in bytes) of files belonging
           // to snapshots over this interval
           "size": 0,
           // (integer) number of distinct URLs used to start snapshots in this
           // interval
           "urls": 0,
           // (integer) number of distinct files.hosts represented in snapshots
           // over this interval
           "hosts": 0
       }
     #+end_src
*** Request
    Content-Type: application/json
    #+begin_src json-ts
      {
          // (array of intervals) intervals over which to return statistics
          "intervals": [...]
      }
    #+end_src
*** Success Response
    Code: 200 (OK) \\
    Content-Type: application/json
    #+begin_src json-ts
      {
          // (array of statistics) statistics over the requested intervals
          // the order of this is the same as the request
          // if the request array was empty, this should just be an empty aray
          "statistics": [...]
      }
    #+end_src
*** Error Response
    Only the global error responses defined above apply.
